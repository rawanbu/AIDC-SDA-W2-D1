\# W2D1: First Contact\## Model and GPU\- Model: `Qwen/Qwen2.5-1.5B-Instruct`\- GPU: `Tesla T4`\- GPU memory: 16 GB\## PredictionUsing the formula:`memory ≈ number of parameters × bytes per parameter`The model has approximately 1.5 billion parameters.| dtype | Predicted weights ||---|---:|| fp16 | 3.0 GB || int8 | 1.5 GB || int4 | 0.75 GB |For fp32, the weights alone are approximately 6.0 GB. However, the actual GPU requirement also includes CUDA overhead, activations, KV cache, and other memory allocations.\## Measured Results| dtype | predicted GB | measured GB | observed bytes/param | tokens/s ||---|---:|---:|---:|---:|| fp16 | 3.0 | 3.29 | 2.19 | 31.1 || int8 | 1.5 | 1.87 | 1.25 | 5.5 || int4 | 0.75 | 1.24 | 0.83 | 14.0 |\## ObservationsThe measured VRAM usage is higher than the theoretical weight-only prediction for all three precisions. This difference comes from GPU and CUDA overhead, allocator memory, buffers, and other tensors required during model loading and inference.FP16 achieved the highest generation speed at 31.1 tokens/s. Int8 was the slowest at 5.5 tokens/s, while int4 achieved 14.0 tokens/s. The quantized models used less VRAM than fp16, but they were slower on this T4 in this experiment.The results demonstrate that parameter-count calculations provide a useful estimate of model memory, but actual GPU memory usage depends on additional runtime overhead and inference-related memory.\## Context ExperimentThe fp16 model was also tested with increasing context lengths to observe the effect of KV cache and activations on GPU memory usage. As context length increases, the memory required during generation increases as well.\## Deliverables\- `generate.py`\- `results.json`\- `README.md`## W2D3 Image Size Comparison| stage | image size ||---|---:|| naive build (full base, cached pip) | 16.5 GB || slim build | 1.61 GB |The slim image is about 14.89 GB smaller (~90.2% reduction).
